## 1. 项目概述

### 1.1 背景

当前系统后端已实现完整的余额管理功能（余额查询、充值、扣减、日志记录），但前端"我的"页面显示的余额数据是硬编码的，用户无法看到真实的余额信息和交易记录。

### 1.2 目标

- 在前端"我的"页面显示用户的真实余额
- 提供余额明细查询功能（账单记录、消费记录、充值记录）
- 完善充值功能（在线支付 + 银行转账）
- 显示转账凭证审核状态

### 1.3 范围

**包含**:
- 前端余额显示修复
- 余额明细页面开发
- 充值功能完善
- 转账凭证状态显示

**不包含**:
- 折扣记录功能（优惠券、会员折扣）- 未来功能
- 后端余额管理核心逻辑修改（已完整实现）
- 支付网关集成（已实现）

### 1.4 用户角色

| 角色 | 描述 | 权限 |
|------|------|------|
| 普通用户 | 使用集运服务的客户 | 查看余额、充值、查看明细 |
| 管理员 | 后台管理人员 | 审核转账凭证、手动充值 |

### 4.2 数据字典

#### 余额变动类型 (sence_type)

| 值 | 名称 | 说明 |
|----|------|------|
| 1 | 增加 | 充值、退款等 |
| 2 | 减少 | 消费、支付等 |

#### 转账凭证状态 (status)

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | 待审核 | 刚提交，等待管理员审核 |
| 1 | 已通过 | 审核通过，余额已到账 |
| 2 | 已拒绝 | 审核未通过，需要重新提交 |

#### 币种 (coin_type)

| 值 | 名称 | 符号 |
|----|------|------|
| 1 | 人民币 | ¥ |
| 2 | 泰铢 | ฿ |
| 3 | 越南盾 | ₫ |

**本项目使用**: 泰铢 (THB, ฿)

## 5. 约束条件

### 5.1 技术约束

- 前端必须使用 React + Vite + Tailwind CSS
- 状态管理使用 Recoil
- 国际化使用 react-i18next
- 后端使用 ThinkPHP 5.x，不做大规模重构

### 5.2 业务约束

- 余额不能为负数
- 充值金额必须大于0
- 转账凭证必须上传截图
- 管理员审核后才能到账（银行转账方式）

### 5.3 时间约束

- Phase 1 (核心功能): 2-3天
- Phase 2 (充值功能): 2-3天
- Phase 3 (技术债务): 1天
- 总计: 5-7天
